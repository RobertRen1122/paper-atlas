LingBot-World 2.0, Explained

Wan’s DiT turned into a world model: block-causal chunks against a sinking KV cache, four steps per chunk, and a camera in every block.

What it is. LingBot-World 2.0 (“LingBot-World-Infinity”, Robbyant) is an interactive world model built on the Wan 2.2 I2V stack: same 14B block dimensions (5120 × 40 blocks, head_dim 128), same Wan2.1 VAE, same UMT5 and mask+latent conditioning. Everything else changes regime: generation is autoregressive in chunks of 4 latent frames, attention is block-causal against a rolling KV cache with an attention sink, sampling is a distilled 4-step x₀-renoise loop with no CFG, and camera poses modulate every block. Notably, the repo ships Wan’s bidirectional model.py but never imports it, and Wan2.2’s two-expert design is abandoned — boundary=0.947 survives in the config as a fossil (image2video.py:23, configs:33).

Grounding. Unlike Wan 2.2, this release has a real paper — paper.pdf in the repo root, also arXiv:2607.07534 (19 pp.) — used here for training-time and deployment facts. Architecture facts come from the code at commit 2648877 (clean checkout; line links match local files). The canonical run is the release script run_fast.sh: 8×GPU Ulysses, 480×832, 361 frames, --local_attn_size 18 --sink_size 6. Only the 14B causal-fast weights are released; causal-pretrain and the paper’s 1.3B are roadmap items (README:56).

1The chunk loop

One prompt, one first frame, and a stream of camera poses go in; video comes out chunk-by-chunk. 361 requested frames become 91 latent frames, floored to 88 (a multiple of the chunk size 4) (image2video.py:498) — so the run is 22 chunks and the saved video has 349 frames. Text is T5-encoded once and its K/V cached for the entire generation (model_fast.py:189); the VAE-encoded first frame rides along as Wan-style 20-channel y.

2A cache that rolls but never forgets its start

Self-attention is block-causal: the 4 frames of a chunk attend to each other bidirectionally and to the cache of past frames — there is no mask inside the chunk, and no access beyond the cache (model_fast.py:157). When the rolling buffer overflows, eviction shifts everything left except the first sink_size frames, which are pinned forever (:133) — an attention sink holding the scene’s establishing frames. Temporal RoPE uses absolute frame indices offset by the chunk’s position (:22).

3Five forwards per chunk, no CFG

The distilled model never runs a solver in the usual sense. Per chunk it makes four predictions at fixed timesteps — indices [0, 250, 500, 750] of a 1000-point shift-10 schedule (image2video.py:530, :393) — each converted straight to a clean-video estimate x₀ = xₜ − σₜ·v (:363), then re-noised with fresh noise to the next, lower timestep (:695). No negative prompt, no second pass: classifier-free guidance exists only in the unreleased causal_pretrain mode, where it doubles every cache (:876).

4The camera is a per-block signal

Actions in the released code are camera trajectories (poses.npy + intrinsics.npy per example directory). Per-video poses are SLERP-interpolated down to latent-frame rate, converted to frame-to-frame relative motion with translations normalized to unit max-norm (cam_utils.py:56), and rendered as Plücker ray maps — a 6-vector (ray origin, ray direction) per pixel (:95).

5What you can run vs. what the demo runs

The README’s headline numbers — 720p, 60 fps, hour-long sessions, agentic events — describe the deployed system in the paper’s §4, most of which is not in this repository. The repo is the model plus an offline chunked sampler; the config saves video at 16 fps (shared_config.py:17).

Worth knowing from the paper

  • MoBA mask (§3.2). Pretraining uses a teacher-forcing mask (noisy frame attends to itself + clean past) with a bidirectional block appended — pure teacher forcing made the model lean on context and degrade as context grew. Cross-attention gets a matching causal mask: chunk-wise prompts lower-triangular for the causal part, one global prompt for the bidirectional part. Chunk-wise captions are also how the data engine annotates training video (§2.3).
  • Objective. Conditional flow matching with velocity target ε − x — exactly the convention the pipeline inverts in _convert_flow_pred_to_x0.
  • Distillation (§3.3). Consistency distillation (EMA teacher, trajectory-invariant student) plus DMD where the fake-score critic runs over long self-rollouts rather than teacher-forced states — the anti-drift ingredient behind the hour-long stress test (Fig. 10: one 60-minute session across 20 scenes with no visible decay).
  • Agentic harness (§4.2). A VLM “Director” reads the scene and proposes event cards (optionally SAM-tracked per object); the DiT “Pilot” grounds them into rollouts. UI: WASD moves, IJKL looks, Space/P fixed actions, U/O/F/G VLM-proposed actions, numeric keys user-registered events (§4.4). None of this code ships in the repo.
  • Stated limitations (§6). The world is “persistent in appearance but not in identity”: regions that leave the context window are regenerated, not recalled; characters and style can drift over very long rollouts; physics is learned from pixels, so objects occasionally interpenetrate. Long-term memory is named the open problem.
  • Model family. The paper pairs the 14B with a 1.3B for single-GPU deployment; only the 14B causal-fast checkpoint is public so far. Table 1 positions this as the only open model with hour-level generation; closed comparisons include Genie 3 and HappyOyster.
  • Data engine (§2). Egocentric + game/Unreal synthetic + web video; TransNet V2 shot slicing, technical scoring, VLM profiling; multi-track event-level annotation composed into chunk-wise captions — built to give the time-localized supervision the chunk-wise conditioning needs.
