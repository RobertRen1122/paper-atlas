Wan 2.1, Explained

The complete architecture in eight figures — pipeline, DiT block, VAE, streaming, and the I2V graft

Every number on this page is one canonical run, traced through the released code at a pinned commit: the 14B text-to-video model generating one 480×832, 81-frame video. Wan 2.1 has exactly four mechanisms: a sampling loop that calls a diffusion transformer 100 times in latent space, a causal VAE that moves between pixels and that latent space, and a small conditioning graft that turns the same backbone into an image-to-video model. One figure per mechanism, plus close-ups where the density lives.

1The generation pipeline

Text is encoded once; everything else is a loop in [16, 21, 60, 104] latent space — 16 VAE channels, 21 latent frames ((81−1)/4+1), 60×104 latent pixels (480/8, 832/8). Pixels exist only after the final decode.

2The DiT block

The DiT box above is 40 identical copies of one ~25-line block wrapped in a patchify (16→5120-dim tokens) and its inverse. The stream keeps shape [1, 32760, 5120] through all of them; blocks only ever add to it. What makes it a diffusion transformer is in violet: six per-channel signals from the timestep that scale, shift, and gate every write.

3Wan-VAE

The VAE is where perception happens: a deep causal 3D conv network compressing 4× in time and 8×8 in space into 16 channels — ≈48× fewer values — so that 100 DiT calls run on 32,760 tokens instead of half a million.

4Chunk-to-chunk streaming

The one place Wan 2.1 works chunk-to-chunk is the VAE. To keep peak memory constant in video length, encode splits the frames into chunks of 1, then 4, 4, 4, … and pushes each through the full network separately; decode goes latent frame by latent frame. This is processing, not generation — the DiT has already denoised everything jointly — and it is exact: chunked output equals full-video output, because of one small mechanism at every conv (Fig. 7). To build intuition for the causal convolution itself, try the interactive CausalConv3d playground — rotate the volume, scrub the kernel through time, and flip between causal and centered padding.

5The I2V graft

Image-to-video is the same backbone with one graft: the reference image enters twice, once as meaning and once as pixels. Everything else — blocks, VAE, sampling — is unchanged.

6Worth knowing from the tech report (arXiv 2503.20314)

  • Full 3D attention was a deliberate bet. Earlier video DiTs factorized attention into spatial + temporal passes to save compute; Wan attends over all 32,760 spacetime tokens jointly and lets scale pay for it. That choice is why the token budget (and the VAE’s 4×8×8 compression) matters so much.
  • Wan-VAE was designed for unbounded length — causal padding + the feature cache (Figs. 6–7) give constant-memory encode/decode of arbitrarily long video, and causality makes an image a 1-frame video, enabling joint image–video training.
  • Flow matching, not DDPM. Training draws t, interpolates x t = (1−t) x₀ + t ε, and regresses the velocity ε − x₀; sampling is 50 solver steps. The shift=5 warps sampling timesteps toward high noise, where video structure is decided (higher shift recommended at higher resolution / for the small model).
  • Training was progressive: images and low-res video first, then increasing resolution/duration — the same weights serve 480p and 720p.
  • UMT5 was chosen for bilingual prompting (the model renders Chinese and English text in-video, a headline capability), and the default negative prompt ships as a Chinese defect list.
  • Prompt extension matters: the released pipeline optionally rewrites your prompt with an LLM (prompt_extend.py) — the paper reports it improves detail and motion.
