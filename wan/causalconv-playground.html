What you are looking at

Eight video frames (f0 – f7) stand as slabs along the time axis; each slab’s face is that frame’s H×W grid (channels are folded into each cell — the kernel always spans all of them). The floating cube is one output value; the amber box is the 3×3×3 window of inputs it reads: 3 frames × 3 rows × 3 columns. Slide the output through time and the window slides with it.

The entire “causal” trick is the padding

A kernel-3 conv needs one extra frame on each side to keep the same length. Centered padding (the default everywhere else) splits it 1+1, so the window at t is [t−1, t, t+1] — output t reads the future. Causal padding puts both frames on the left (vae.py:24-26), so the window is [t−2, t−1, t]: same output length, zero future. Flip the toggle and watch the window shift off the future — that one asymmetry is the whole mechanism. At t=0 the window is [pad, pad, f0]: the first frame depends only on itself, which is why an image is a valid 1-frame video.

The cache is just better padding

Switch left context to Cached chunk: the two grey zero-slabs become the violet last-2-frames of the previous chunk (vae.py:28-36). Every window is then identical to what a full-video pass would see, so chunked streaming is bit-exact. One layer reaches 2 frames back; N stacked layers reach 2N — always backward, never forward. The stride-2 downsampling convs are the same idea with kernel 3, stride 2, and one cached frame.
