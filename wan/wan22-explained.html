What Wan 2.2 is. Three released model families in one repo, all built from the Wan 2.1 parts bin: T2V-A14B and I2V-A14B keep Wan 2.1’s VAE and transformer block but split denoising across two 14B experts — one for high noise, one for low — selected per timestep; and TI2V-5B, a single dense model that does both text- and image-to-video on top of a new, much more aggressive VAE. The transformer block, UMT5 text encoder, RoPE layout (22/21/21 frequency pairs on head_dim 128 — identical in both model sizes), and UniPC flow-matching sampler are unchanged from 2.1 — read that page first; this one covers only what moved.

Grounding. There is no Wan 2.2 technical report: the README’s own “Paper” link (README:8) points to the Wan 2.1 report, arXiv:2503.20314. Every architecture fact below is read from the code at commit 42bf4cf (clean checkout, so line links match your local files); training-side claims are quoted from the README and marked as such.

1One trajectory, two 14B experts

The pipeline is Wan 2.1’s with one structural change inside the loop: two full copies of WanModel are loaded from subfolders high_noise_model and low_noise_model (text2video.py:101), and each denoising step routes to exactly one of them by comparing the timestep against boundary × 1000 (:186, :306). The CFG scale switches with it — the guide scale is a pair now (configs:37, text2video.py:343).

2Where the handoff actually lands

The boundary is a fraction of training time (0.875 for T2V, 0.900 for I2V), but the number of steps each expert serves depends on the sigma shift, which warps where the 40 sampled timesteps fall (fm_solvers_unipc.py:184). 3The block: one silent change

Diffing modules/model.py against 2.1 shows the block untouched except for two things: the image-branch cross-attention (2.1’s WanI2VCrossAttention with its CLIP-fed k_img/v_img) is deleted outright, and the AdaLN signal grew a token axis. forward() now accepts a timestep vector and builds one 6-way modulation tuple per token (model.py:460, :237). A14B always passes a uniform vector, so it behaves exactly like 2.1 — the machinery exists for TI2V (§5), where conditioned tokens run at t = 0 while the rest denoise.

4I2V loses the CLIP crutch

Wan 2.1’s I2V fed the image in twice: 257 CLIP tokens through an extra cross-attention branch, plus the VAE-encoded first frame concatenated on channels. Wan 2.2 keeps only the second path. There is no CLIP checkpoint, no clip_fea argument, no image cross-attention — conditioning is purely the 20-channel y stack, and the expert pair plus boundary 0.900 do the rest (image2video.py:289–323).

5TI2V-5B: the high-compression track

The third release is a single dense 5B model (dim 3072, 30 blocks, 24 heads — same head_dim 128) with no experts and no boundary. What makes it fast is the Wan2.2-VAE: a pixel-unshuffle patchify feeds 12 channels into the causal conv stack (vae2_2.py:785, :525), giving 4×16×16 total compression into 48 latent channels — so 121 frames of 704p become just 27,280 tokens, a third of A14B’s count for 50% more frames at 24 fps.

Worth knowing from the README

  • Why two experts. Capacity up, cost flat: “a total of 27B parameters but only 14B active per step, keeping inference computation and GPU memory nearly unchanged” (README:450). Note this is timestep-routing, not per-token learned-router MoE in the LLM sense.
  • Where the boundary comes from. The README derives the switch point tmoe from the signal-to-noise ratio — the step where SNR falls to half of SNRmin (README:456). The released code never computes SNR; the result is hard-coded as 0.875 / 0.900 in the configs.
  • The ablation. Validation loss: full two-expert Wan 2.2 beats both hybrids that reuse Wan 2.1 as one of the experts, and the 2.1 baseline (README:462).
  • Data, not architecture, for motion. The claimed driver of quality: +65.6% images, +83.2% videos over 2.1’s training set (README:24). Training-side; not verifiable in this repo.
  • TI2V-5B speed claim. 5 s of 720p24 in under 9 minutes on one consumer GPU (24 GB, e.g. RTX 4090); counting the DiT’s own 2×2 patchify, total compression reaches 4×32×32 (README:466, :233).
  • Two code-vs-docs mismatches. The t2v generate() docstring advertises 50 steps / CFG 5.0, but the release script passes the config’s 40 steps / (3.0, 4.0) (text2video.py:203); and masks_like carries a training-time noise-augmentation branch (p = 0.2 on the pinned frame) that is dead at inference — both call sites pass no generator (utils.py:172).

The other two members. S2V-14B (speech-to-video) is a 2.1-VAE 14B DiT with an audio encoder (audio_dim 1024) injected per block, generating long videos autoregressively clip-by-clip with motion frames as memory — the closest thing in this repo to LingBot’s causal loop — and it has its own report, arXiv:2508.18621 (configs). Animate-14B does character animation/replacement from a driving video via a pose-retargeting preprocess, a motion encoder (dim 512), and an optional relighting LoRA; report at arXiv:2509.14055 (configs). Neither touches the A14B/TI2V pipelines above.
