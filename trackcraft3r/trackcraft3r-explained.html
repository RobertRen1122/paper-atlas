TrackCraft3R, Explained

A video DiT turned into a one-pass dense 3D tracker — dual latents, temporal RoPE alignment, and the two-line I/O surgery that makes it work

Video diffusion transformers generate frames: every token is anchored to the content of its own timestamp. Dense 3D tracking wants the opposite — follow the pixels of frame 0 as they move through every later frame. TrackCraft3R (KAIST & Google DeepMind, arXiv 2605.12587) closes that gap without touching the transformer’s architecture. It feeds Wan 2.1’s DiT two token streams built from the same VAE latents, gives the second stream a borrowed timestamp through RoPE, runs the model once at a near-zero timestep, and decodes the second stream into a residual 3D track and a visibility map. Everything below is drawn from the release code at commit 21e8fca (a DiffSynth-Studio fork), traced at the README’s own defaults; the paper supplies the training facts and the why. Where the two disagree, §8 says so.

1The tracking pipeline

Inputs are a monocular clip plus per-frame depth and camera from an off-the-shelf estimator (Depth-Anything-3, ViPE, or ground truth). RGB frames and unprojected pointmaps go through separate Wan VAE encoders; the resulting latents are packed into two 32-channel streams, run through the DiT in a single forward, and only the second stream’s outputs are decoded — through two more VAE decoders — into a residual track and a visibility map.

2Dual latents: a matrix with a diagonal and a row

The paper’s cleanest idea is a change of indexing. Write Pi(tj) for the 3D positions of the pixels of frame i at time j. What a depth estimator gives you is the diagonal of that matrix — each frame’s own content at its own time. What a tracker must produce is row 0 — frame 0’s content at every later time. The code literally uses those words: the geometry stream is diagonal, the track stream is row.

One more thing has to be true for the matrix picture to hold: every latent frame must correspond to exactly one video frame. Wan’s causal VAE compresses time 4× after the first frame, which would blur four frames into one latent and break the per-frame residual. TrackCraft3R sidesteps the temporal stack entirely.

3Temporal RoPE alignment: lending each query a timestamp

A track token rj is a copy of g0, so nothing in its content says “I am asking about time j.” The timestamp is supplied by position: the 3D RoPE table is built for 12 frames and then duplicated, so the track token at latent frame j receives exactly the rotary phase of the geometry token at frame j. Rotary attention scores depend only on relative offsets, so a zero temporal offset is the strongest possible pull — rj looks at gj.

4The DiT block, and where the LoRA lands

The transformer is Wan 2.1’s block, unmodified: adaLN-modulated self-attention with RoPE, cross-attention to the text context, adaLN-modulated FFN, gated residuals. What changes is (i) the timestep is a constant, so every block’s shift/scale/gate is a fixed vector; (ii) the text is a null prompt, so cross-attention keys and values are the same 512 tokens for every clip; and (iii) LoRA adapters of rank 1024 wrap every attention projection and both FFN linears. At width 1536, rank 1024 is not “low”: the adapters carry slightly more parameters than the weights they modify.

5The I/O surgery: 16 in, 16 out → 32 in, 32 out

Wan’s patch embedding expects 16 latent channels and its head emits 16. TrackCraft3R doubles both, and the way it initializes them is a small design in itself: the new input half is a copy of the RGB filters, so on day one the model sees the pointmap latent through the lens it already knows; the new output half is zero, so visibility starts as a silent channel and cannot disturb the pretrained xyz path.

6Long videos: one anchor, interleaved passes

The model is trained on 12-frame clips. Longer videos are not chained — chaining is what the paper argues against in MotionCrafter — but interleaved: frame 0 stays the anchor of every pass, and the remaining frames are dealt into s strided groups so that each pass still sees exactly 12 frames. Because every pass predicts P0(tj) in the same frame-0 camera frame, the outputs need no alignment; where passes overlap they are simply averaged.

7Worth knowing from the paper (arXiv 2605.12587)

  • Data. Four synthetic datasets, ground-truth 3D trajectories from mesh vertices: Kubric (6,042 rendered 480×832×81-frame sequences, strides 3–7), Dynamic Replica (483, strides 5–9), PointOdyssey (45, strides 2–6), and static-scene TartanAir (163, strides 1–3) for ego-motion robustness (Table 7). The release scripts encode the same four configs with the same strides (train_stage1.sh:40). The appendix contrasts this with V-DPM’s 23 3D-annotated datasets and argues web-video pretraining substitutes for most of it.
  • Two-stage training on 8×H200. Stage 1: LoRA + the two projections, VAEs frozen, AdamW 1e-4, global batch 80, 3 days. Stage 2: unfreeze all four VAE roles, 3e-5 for the DiT and 1e-5 for the VAEs, batch 64, 2 more days (§5.1). The scripts match: batch 10×8 and 8×8 processes, the same learning rates, cosine decay to 3e-5 / 1e-5 over 10k steps (train_stage1.sh:28, train_stage2.sh:31).
  • Ablations (Table 3, VAE frozen, average AJ / APD3D / OA). Full model 0.561 / 0.679 / 0.923. Without first-frame anchoring 0.514 / 0.654 / 0.878; without temporal RoPE alignment 0.445 / 0.632 / 0.803 (largest AJ drop); without the residual 0.501 / 0.617 / 0.916 (APD3D suffers most); with VAE temporal compression 0.449 / 0.633 / 0.815. Random init instead of Wan weights: 0.470 / 0.631 / 0.827 (Table 2).
  • Rank and VAE fine-tuning (Table 5). LoRA rank 64 / 256 / 1024 → AJ 0.503 / 0.540 / 0.561; unfreezing the VAEs in Stage 2 adds a little more, 0.564 / 0.682 / 0.926.
  • Bounded by input geometry (Table 4). On the synthetic benchmarks, swapping DA3 depth/pose for ground truth lifts AJ from 0.601 to 0.765 with no retraining — better 3D foundation models translate directly.
  • Efficiency (Table 6, 448×448, one A6000). 12 frames: 3.91 s and 7.63 GB, vs DELTAv2’s 5.00 s / 35.46 GB (the paper’s 1.3× / 4.6×); 23 frames: 7.84 s at the same 7.63 GB. Against V-DPM (Table 11): 3.2× faster at 12 frames, 6.6× at 23. At 448×448 the sequence is 28×28×24 = 18,816 tokens, half the canonical run above.
  • Where attention goes (App. E). Averaged over layers, a track token puts 29.0% / 30.1% (two examples) of its attention on the temporally aligned geometry frame; certain layers do the correspondence search and the same layers do it across samples.
  • Robustness (Fig. 5). With 12-frame clips, stride swept 1→12 and length 12→120: the gap to DELTAv2 widens in both directions.
  • Stated limitation and direction. Accuracy is capped by the external depth/pose; the authors point at jointly generating video and tracks in one DiT as the next step (App. G).

8Paper vs. code: what the release pins down

Nothing here contradicts the paper’s claims; these are the places where the paper is silent or approximate and the code is exact, plus one piece of vocabulary worth having.
